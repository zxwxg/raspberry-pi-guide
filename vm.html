Try Raspberry Pi in a virtual machine

A virtual machine (VM) is a computer inside your computer. You install a program (VirtualBox, VMware, QEMU), give it some RAM and disk space, and it boots a full operating system in a window — without touching your real system or buying anything. Here is every method, with the exact settings and commands.

Works on Windows, macOS, Linux Zero cost Safe — you cannot break your PC Setup time: 15–45 minutes

✅ What a VM teaches you perfectly

  • The Raspberry Pi OS desktop, menu and file system
  • The terminal: files, permissions, apt, services
  • SSH, static IPs, networking basics, port forwarding
  • Installing and running servers: nginx, Pi-hole, Home Assistant, Docker
  • Python, bash scripting, cron jobs, Git
  • The exact same commands that work on the real board

❌ What a VM cannot do

  • Drive GPIO pins, LEDs, motors, relays or sensors
  • Use the camera connector or the official display
  • Use HATs (Sense HAT, AI HAT+, M.2 HAT+)
  • Measure real performance — emulation is far slower than silicon
  • Behave exactly like ARM on the x86 "Desktop" edition (different CPU, different packages in rare cases)

Rule of thumb: learn everything in the VM, then buy the board for the physical parts.

Before you start, know the numbers. Give any VM at least 2048 MB RAM, 2 CPU cores and 20 GB disk. Anything less and the desktop will feel broken, which is not the Pi's fault — it is the VM's.

Method 1 · recommended first

VirtualBox + Raspberry Pi Desktop (x86)

The Raspberry Pi Foundation publishes a PC/Mac edition of its desktop environment as a bootable ISO. It is Debian with the Raspberry Pi look, menu, tools and programming software — running natively on your Intel/AMD CPU, so it is fast.

  1. Install the virtual machine host

    Download VirtualBox (free, GPL) from virtualbox.org and install it with default options. Windows users: accept the network driver install prompt.

    Alternatives: VMware Workstation Player (now free for personal use on Windows/Linux), or VMware Fusion (free for personal use on Mac).

  2. Download the Raspberry Pi Desktop ISO

    Go to raspberrypi.com/software and choose Raspberry Pi Desktop for PC and Mac (a ~3 GB ISO). Under the "Other" section you can also find it directly in Raspberry Pi Imager.

    Note: this x86 edition is refreshed less often than Raspberry Pi OS for the board. That is fine for learning — the desktop, terminal and tools behave the same.

  3. Create the virtual machine

    VirtualBox → New. Fill in exactly these values:

    NameRaspberry Pi Desktop
    Type / VersionLinux / Debian (64-bit)
    Memory (RAM)2048 MB (4096 if your PC has 16 GB)
    Processors2 (Settings → System → Processor)
    Hard disk20 GB VDI, dynamically allocated
    Graphics controllerVMSVGA, 128 MB video memory
    NetworkNAT (default)
    EFIDisabled (use BIOS) unless the ISO refuses to boot

  4. Attach the ISO and start

    Settings → Storage → click the empty CD icon → Choose a disk file → select the ISO. Press Start. When the boot menu appears, choose Install (or "Live" first to test without installing).

  5. Follow the Debian installer

    Language, keyboard, "Guided — use entire disk", one user with a password. The whole installation takes 5–10 minutes. When it reboots, you land on the Raspberry Pi desktop.

  6. Make it comfortable

    Install guest additions for bigger screens, shared folders and clipboard:

    sudo apt update && sudo apt upgrade -y
sudo apt install -y virtualbox-guest-dkms virtualbox-guest-utils virtualbox-guest-x11
sudo reboot

    Then: Devices → Shared Folders → add a folder from your PC so you can move files in and out.

  7. Take a snapshot

    Machine → Take Snapshot, name it "clean install". From now on you can experiment wildly and roll back in seconds — a luxury you do not get on real hardware. Do this before every risky change.

Terminal practice list (do all ten)

These are the exact commands you will use on a real Pi. Type them, break them, repeat.

# 1. who am I and where am I
whoami && pwd && hostname

# 2. system info: CPU, RAM, temperature
cat /proc/cpuinfo | head -20
free -h
vcgencmd measure_temp 2>/dev/null || echo "no vcgencmd on x86"

# 3. disk usage
df -h

# 4. install software
sudo apt update
sudo apt install -y htop neofetch

# 5. create files and folders
mkdir -p ~/projects/hello && cd ~/projects/hello
echo "print('hi from my Pi')" > hello.py
python3 hello.py

# 6. permissions — make a script executable
printf '#!/bin/bash\necho "running"\n' > run.sh
chmod +x run.sh && ./run.sh

# 7. services and logs
systemctl status ssh
journalctl -xe | tail -30

# 8. schedule something
crontab -e   # add: */5 * * * * date >> ~/time.log

# 9. networking
ip a
ping -c 4 1.1.1.1

# 10. find your first server
sudo apt install -y nginx
hostname -I

Then open a browser inside the VM and visit http://localhost — you have just run a web server.

💡

Teaching tip: a VM is the safest classroom there is. Students can run rm -rf, break the desktop, fill the disk — and you just roll back the snapshot. This is how you teach system administration without fear.

Method 2 · most authentic

QEMU — emulate the real ARM Raspberry Pi

QEMU simulates ARM hardware in software. You boot an actual Raspberry Pi OS image — the same one you would write to a microSD — so what you learn transfers perfectly. The price is speed: the emulated CPU runs maybe 5–20× slower than real silicon. Use the Lite (no desktop) image for speed, or the desktop image if you are patient.

  1. Install QEMU

    Windows: download the official 64-bit installer from qemu.org/download and tick "Add QEMU to the system PATH". Verify by opening PowerShell:

    qemu-system-aarch64 --version

    Ubuntu/Debian/WSL: sudo apt install qemu-system-arm · macOS: brew install qemu

  2. Get the Raspberry Pi OS image

    Download Raspberry Pi OS (Lite recommended, 64-bit) from raspberrypi.com/software. While it is selected in Raspberry Pi Imager, press the gear/"Edit settings" button and set:

    • hostname, username and password
    • Wi-Fi (leave blank if using QEMU's built-in network)
    • Enable SSH with password authentication

    Doing this now means the VM boots with SSH already on — no monitor required.

  3. Grow the disk image (do this once)

    Raspberry Pi OS auto-expands to fill the card on first boot, so give it room first:

    qemu-img resize 2026-03-01-raspios-bookworm-arm64-lite.img +8G

    On Windows, run this from the folder containing the .img file. Keep the exact filename — version numbers change.

  4. Get a kernel and device tree for the emulated board

    QEMU's "raspi3b" machine needs a QEMU-friendly kernel: kernel8.img and a .dtb file. The community project github.com/dhruvvyas90/qemu-rpi-kernel provides prebuilt ones — download kernel8.img and bcm2710-rpi-3-b-plus.dtb into the same folder as your image.

    Alternative (Linux/macOS): mount the boot partition of the .img and copy its own kernel8.img and bcm2710-rpi-3-b-plus.dtb, which is more version-accurate.

  5. Boot it — Linux / macOS / WSL

    The backslash at the end of each line continues the command on the next line:

    qemu-system-aarch64 -M raspi3b -cpu cortex-a53 -m 1024 \
  -kernel kernel8.img -dtb bcm2710-rpi-3-b-plus.dtb \
  -sd 2026-03-01-raspios-bookworm-arm64-lite.img \
  -append "console=ttyAMA0 root=/dev/mmcblk0p2 rw fsck.repair=yes rootwait" \
  -serial stdio \
  -usb -device usb-kbd -device usb-mouse \
  -device usb-net,netdev=n0 -netdev user,id=n0,hostfwd=tcp::2222-:22

  6. Boot it — Windows PowerShell

    PowerShell does not understand \ as a line continuation (it uses a backtick). Easiest: paste it as one line:

    qemu-system-aarch64 -M raspi3b -cpu cortex-a53 -m 1024 -kernel kernel8.img -dtb bcm2710-rpi-3-b-plus.dtb -sd raspios-lite.img -append "console=ttyAMA0 root=/dev/mmcblk0p2 rw fsck.repair=yes rootwait" -serial stdio -usb -device usb-kbd -device usb-mouse -device usb-net,netdev=n0 -netdev user,id=n0,hostfwd=tcp::2222-:22

  7. Be patient, then log in

    First boot takes 10–30 minutes under emulation (it resizes the filesystem and regenerates SSH keys). You will see text scrolling in the terminal. When the login prompt appears, log in with the username you set in Imager.

    From a second terminal on your PC, SSH in — QEMU forwards port 2222 to the VM's port 22:

    ssh -p 2222 pi@127.0.0.1

  8. Desperate for the graphical desktop?

    Use the full Raspberry Pi OS image and drop -serial stdio so QEMU shows the emulated framebuffer in its own window. Expect everything to be slow — that is normal. The Lite image + SSH is the productive path.

Command flags explained

  • -M raspi3bemulate a Raspberry Pi 3 model B (max 1 GB RAM)
  • -cpu cortex-a53the ARM CPU core the Pi 3 uses
  • -m 10241 GB of emulated RAM (the machine's limit)
  • -kernel/-dtbthe ARM kernel and hardware description QEMU boots
  • -sd file.imgyour microSD image, mounted as the VM's disk
  • -append "…rootwait"kernel boot arguments; root= is the second partition
  • -serial stdiosend the console to your terminal
  • -device usb-netgives the VM a network card
  • hostfwd=tcp::2222-:22your PC's port 2222 → VM's SSH port
⚡

Performance reality check. Software emulation of an ARM CPU on an x86 PC is inherently slow — a build that takes 30 seconds on a real Pi 5 can take 10 minutes here. That is exactly why QEMU is great for learning and testing and bad for measuring.

Can you use QEMU with hardware acceleration instead? On Apple Silicon use -M virt -accel hvf with a generic Debian/Ubuntu ARM64 image (very fast, but it is not a "Raspberry Pi" machine). On Intel/AMD there is no KVM for ARM guests, so the raspi machines always run emulated.

🐧

Windows shortcut: install WSL2 (wsl --install -d Ubuntu), then sudo apt install qemu-system-arm and run the Linux command above inside WSL. You avoid all PowerShell quoting problems and get a much nicer terminal.

Alternatives

Three more ways to get the experience

3 · VMware / Parallels on Apple Silicon + Debian ARM64

On an M-series Mac, virtualising ARM is native and fast. Install VMware Fusion (free for personal use) or Parallels, then install Debian ARM64 or Ubuntu Server ARM64 from an ISO. Add the desktop with tasksel or apt install xfce4, then install the same software you would on a Pi (nginx, Docker, Home Assistant).

It is not Raspberry Pi OS, but it is real ARM Linux — the closest free equivalent with native speed.

sudo apt update
sudo apt install -y xfce4 xfce4-goodies
sudo apt install -y python3 docker.io nginx

4 · Docker container for command practice

If you only want to practise Linux commands, a container is instant and free. It shares your PC's kernel — so no boot, no desktop, no GPIO — but every terminal command works identically.

# an ARM Raspberry Pi OS userland container
docker run -it --rm --platform linux/arm64 \
  balenalib/raspberry-pi-debian:bookworm bash

# or a plain Debian for general practice
docker run -it --rm debian:12 bash

Install Docker Desktop on Windows/macOS. Note: some ARM images run through emulation (QEMU is bundled into Docker Desktop), which is slow but works.

5 · Borrow a real Pi remotely

The most underrated option: many schools, makerspaces, universities and libraries have Pis you can log into, and there are online labs that give you a real board over the internet. You get 100 % real behaviour — including GPIO — with no purchase.

  • Ask a local school/college lab for a temporary account
  • Join a makerspace or public library coding programme
  • If you have a friend with a Pi, ask for an SSH account and create your own user: sudo adduser you

A real Pi 5 draws ~4 W idle — running one for a friend costs about $1 of electricity per month. It is the cheapest way to get a real machine.

The 12-point setup checklist

Do these once in the VM — and again on your real board. They are the difference between a toy and a reliable machine.

Essential

Strongly recommended

Back up the system like a pro

On real hardware, back up the whole microSD card to an image file on your PC. In the VM, it is even easier — use snapshots.

# Linux / macOS: copy the SD card to an image
sudo dd if=/dev/sdX of=pi-backup-$(date +%F).img bs=4M status=progress

# Windows (Administrator PowerShell): find the disk number first
Get-Disk | Format-Table Number, FriendlyName, Size
wmic diskdrive get index,caption,size
# then use Win32DiskImager to "Read" the card into a .img file

# Restore later exactly the same way, using the Write function

Also copy your important config folders: /etc changes, your home directory and docker-compose.yml files. Keep a second copy on another device — a backup on the same machine is not a backup.

Know when something is wrong

These four commands diagnose 90 % of problems — on a VM and on a real Pi:

# 1. is the power/thermal state healthy?
vcgencmd get_throttled     # 0x0 = all good
vcgencmd measure_temp      # keep below 80 °C

# 2. what is eating the CPU or RAM?
top -o %CPU   # or: htop

# 3. why did a service fail?
systemctl --failed
journalctl -u nginx -n 50

# 4. is the disk full or the card dying?
df -h
dmesg | grep -i -E "error|mmc|I/O"

Use the Lite image, avoid the desktop, expect first boot to take 10–30 minutes, and treat it as a test lab rather than a workstation. If you need real performance for free, use an x86 VM or a native ARM VM on an Apple Silicon Mac.

Support for newer boards has been improving, but the well-tested, widely documented machine is raspi3b. Check what your build offers with qemu-system-aarch64 -M help — if you see raspi4b, you can try it with a matching kernel and device tree. You are using the operating system and the ecosystem, which is the part most people actually interact with daily. What you are not using is the hardware: the GPIO, the cameras, the size, the power efficiency. Think of the VM as the free trial, and the board as the subscription to the real thing.
